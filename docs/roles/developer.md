# Роль: Разработчик

## Миссия
Отвечаю за то, чтобы решение работало под Linux и делало ровно то, что описано в спецификации.

## Зона ответственности

### Разработка решения
- **Выбираю средства разработки** (язык и утилиты) с учётом ограничений заказчика, если они есть.
- **Пишу исходный код и скрипты** для F1–F4 по `docs/spec.md`.
- **Готовлю командные файлы**, например общую точку входа, если так решит архитектура.
- **Готовлю файлы данных**, если они нужны решению.

### Базовое (dev) тестирование
- Перед передачей в тестирование сам проверяю, что функция запускается и работает на обычных данных. Глубокое тестирование — работа QA, но очевидные ошибки отлавливаю я.

### Взаимодействие с командой
- Если спецификация неясна, спрашиваю аналитика, а не додумываю сам.
- Исправляю баги из задач QA. В коммите или PR ссылаюсь на задачу (`Fixes #N`), так история исправлений видна на GitHub.
- Работаю в ветках и через Pull Request .
- Пишу короткий ежедневный отчёт в чате .

## Мои задачи (по порядку)

1. Окружение, выбор средств.
2. Каркас решения.
3. F1, F2 переданы в тестирование.
4. F3, F4 переданы в тестирование.
5. Исправление багов до финальной регрессии.

> Конкретные сроки не фиксируются в документации: они ведутся и обновляются на доске GitHub Projects.

## Взаимодействие

| С кем | Что я даю | Что получаю |
|-------|-----------|-------------|
| **Аналитик** | Вопросы по спецификации, сигнал о нереализуемом | Спецификацию |
| **QA** | Готовые функции для тестирования, исправления | Баги в виде задач |
| **Менеджер** | Статус, оценку сроков, сообщения о блокерах | Задачи и приоритеты |

**Внимание к F3 (удаление):** удаление необратимо, поэтому оно выполняется только после явного подтверждения пользователя. Разрабатываю и проверяю его только на копии данных.
