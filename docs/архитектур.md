# Архитектура программного решения

## 1. Общие сведения

Разрабатываемое решение представляет собой консольное приложение для
операционной системы Linux, предназначенное для обработки файловой
системы преподавателя, подготовленной в рамках лабораторной работы № 3.

Основная задача приложения --- предоставить пользователю единый
интерфейс для получения сведений о посещаемости и результатах обучения
студентов, просмотра досье и формирования рейтинга успеваемости.

На текущем этапе документ описывает проектируемую архитектуру.
Реализация программных модулей будет выполняться последовательно в ходе
разработки.

## 2. Архитектурный подход

В качестве основы выбран модульный подход с единой точкой входа.
Приложение планируется реализовать на Bash с использованием стандартных
средств Linux.

Архитектура предусматривает разделение ответственности между следующими
логическими компонентами:

1.  **Пользовательский интерфейс** --- организация взаимодействия с
    пользователем, отображение меню, получение параметров и вывод
    результатов.
2.  **Модуль управления** --- обработка выбранной команды, проверка
    входных параметров и вызов соответствующей функциональной операции.
3.  **Модули предметной логики** --- выполнение операций анализа
    посещаемости, обработки результатов тестирования, работы с досье и
    формирования рейтинга.
4.  **Компонент доступа к данным** --- определение расположения файлов,
    чтение исходных записей и выполнение предусмотренных операций
    изменения данных.
5.  **Системные средства Linux** --- обработка текстовых файлов и
    сортировка результатов с помощью стандартных команд и встроенных
    возможностей Bash.

## 3. Функциональная структура

В составе решения предусматриваются следующие функциональные модули.

### 3.1. Модуль анализа посещаемости (F1)

Модуль предназначен для определения студентов с наилучшей посещаемостью
в заданной группе за указанный период.

Основные операции: - получение номера учебной группы; - получение
начального и конечного года периода; - выбор одной или нескольких
дисциплин; - чтение файлов посещаемости; - подсчёт посещений и общего
количества занятий; - определение максимального показателя и вывод всех
студентов с одинаковым результатом.

Для определения расчётного года используется год поступления, указанный
в идентификаторе группы, с учётом принятого в проекте правила расчёта
курса обучения.

### 3.2. Модуль анализа результатов тестирования (F2)

Модуль предназначен для определения студента с максимальным общим
количеством правильных ответов в заданной группе.

Основные операции: - получение номера группы; - выбор дисциплины или
нескольких дисциплин; - чтение файлов результатов тестирования; - отбор
записей по группе и идентификатору студента; - суммирование правильных
ответов по всем попыткам; - определение максимального результата и вывод
соответствующего студента или студентов.

### 3.3. Модуль работы с досье студентов (F3)

Модуль обеспечивает поиск и просмотр сведений о студенте, а также
выполнение операции удаления по подтверждению пользователя.

Основные операции: - поиск студента по фамилии или идентификатору; -
обработка случаев совпадения фамилий и идентификаторов; - вывод
доступных сведений о выбранном студенте; - выбор режима удаления; -
запрос подтверждения перед изменением исходных данных; - удаление
выбранных записей с сохранением данных других студентов.

### 3.4. Модуль формирования рейтинга (F4)

Модуль предназначен для формирования упорядоченного списка студентов
заданной группы по показателю успеваемости.

Основные операции: - получение состава группы; - сбор результатов всех
попыток тестирования; - расчёт среднего балла студента; - учёт оценок с
дополнительными знаками «+» и «−» по принятому правилу преобразования; -
сортировка студентов по убыванию среднего балла; - вывод рейтинга с
числовыми значениями.

## 4. Организация хранения и доступа к данным

В качестве источника информации используется файловая система
преподавателя из лабораторной работы № 3.

Предполагается работа со следующими категориями данных:

-   **списки учебных групп** --- идентификаторы студентов, входящих в
    соответствующую группу;
-   **файлы посещаемости** --- записи о посещении занятий по отдельным
    дисциплинам;
-   **файлы тестирования** --- результаты попыток студентов, включая
    дату, количество правильных ответов и оценку;
-   **файлы заметок** --- текстовые сведения преподавателя о студентах.

Приложение не требует предварительного переноса исходной информации в
отдельную базу данных. Доступ к данным осуществляется непосредственно
через файловую систему.

Расположение каталога с исходными данными определяется относительно
расположения исполняемого Bash-скрипта. Каталог `labfiles-3-26` должен
находиться рядом с основным файлом приложения.

## 5. Взаимодействие компонентов

Общий сценарий работы приложения предусматривает следующую
последовательность:

1.  Запуск основного Bash-скрипта.
2.  Проверка доступности каталога исходных данных.
3.  Отображение пользовательского меню.
4.  Получение выбранной операции и необходимых параметров.
5.  Передача управления соответствующему функциональному модулю.
6.  Чтение и обработка необходимых файлов.
7.  Формирование результата и его вывод в консоль.
8.  Возврат к меню либо завершение работы приложения.

Операции, изменяющие исходные данные, выполняются только после явного
подтверждения пользователя.

## 6. Технологические ограничения

При реализации архитектуры предусматривается использование:

-   Bash --- организация логики приложения, функций, условий, циклов и
    арифметических операций;
-   `grep` --- поиск записей в текстовых файлах;
-   `sed` --- обработка текстовых данных;
-   `find` --- поиск файлов и каталогов;
-   `cut` --- извлечение отдельных полей;
-   `sort` --- сортировка результатов;
-   `wc` --- подсчёт строк и записей.

Использование `awk`, `uniq`, Python, SQL и сторонних библиотек в рамках
выбранного подхода не предусматривается.

## 7. Развёртывание и запуск

Решение ориентировано на запуск в Linux. Для эксплуатации достаточно
разместить основной Bash-скрипт рядом с каталогом `labfiles-3-26` и
запустить его из терминала.

Предполагаемая структура размещения:

``` text
Рабочий каталог/
├── lab4.sh
└── labfiles-3-26/
    ├── students/
    ├── Цирковое_Дело/
    └── Пересдачеведение/
```

Такой способ размещения исключает необходимость задавать абсолютные пути
к исходным данным и позволяет переносить рабочий каталог целиком.

## 8. Результат проектирования

Предлагаемая архитектура обеспечивает единый порядок взаимодействия с
файловой системой преподавателя и разделяет решение на функциональные
области F1--F4.

Модульная организация позволяет последовательно разрабатывать и
проверять каждую функцию, не изменяя общую схему работы приложения. По
мере реализации отдельные компоненты будут интегрироваться в единый
консольный сценарий.
