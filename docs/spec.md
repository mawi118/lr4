# Спецификация v1: F1 и F2

Ответственный: аналитик. Эта версия описывает две базовые функции: посещаемость (F1) и правильные ответы (F2). F3 и F4 будут описаны в v2.

Основа требований: `docs/plan.md`. Детали работы программы сверены с `scripts/lab4.sh`. Вопросы без ответа заказчика перечислены в конце документа.

## 1. Данные

Скрипт ищет каталог `labfiles-3-26` рядом с собой. При текущем расположении скрипта это `scripts/labfiles-3-26`. Данные из ЛР 3 пока не добавлены в этот репозиторий, поэтому структура ниже взята из кода и требует проверки на реальной копии.

```text
scripts/
├── lab4.sh
└── labfiles-3-26/
    ├── students/
    │   ├── groups/<группа>
    │   └── general/notes/
    ├── Цирковое_Дело/
    │   ├── <группа>-attendance
    │   └── tests/TEST-*
    └── Пересдачеведение/
        ├── <группа>-attendance
        └── tests/TEST-*
```

- Файл группы содержит один идентификатор студента в строке. Пример имени файла: `A-06-23`.
- Строка посещаемости содержит идентификатор, пробел и последовательность `0` и `1`. `1` означает посещение.
- Строка результата теста содержит поля `группа;студент;дата;правильные_ответы;оценка`.
- F1 и F2 читают данные, но не меняют их. Каталог заметок нужен для общей проверки структуры при запуске, хотя эти функции его не читают.

## 2. Архитектура

Одна точка входа: `scripts/lab4.sh`, Bash-скрипт с функциями для меню, проверки ввода, чтения файлов и расчётов. `main` проверяет каталоги данных, показывает меню и вызывает F1 или F2. `select_subject` выбирает один предмет или оба. F1 использует `attendance_one` и `attendance_all`; F2 использует `collect_tests`. Данные читаются напрямую из текстовых файлов, отдельной базы данных нет.

Для запуска нужны Bash и стандартные средства Linux. В текущем коде расчёты F1 и F2 сделаны средствами Bash. Ключи командной строки и переменная для выбора каталога данных не предусмотрены.

## 3. Интерфейс

Запуск: `bash scripts/lab4.sh` из корня репозитория. Путь к данным зависит от расположения скрипта, а не от текущей директории терминала.

Главное меню:

```text
1. Лучшая посещаемость за период
2. Максимум правильных ответов
0. Выход
```

Ответы вводятся в терминале через stdin. Результаты и меню выводятся в stdout. Сообщения вида `Ошибка: ...` выводятся в stderr. После выполненной операции программа возвращается в меню. `0` завершает работу.

При выборе предмета: `1` - Цирковое дело, `2` - Пересдачеведение, `3` - оба предмета. Для группы используется формат из латинских букв и двух пар цифр через дефис, например `A-06-23`. Группа должна иметь файл в `students/groups/`.

## 4. Функции и формат результата

### F1. Лучшая посещаемость

Требование плана: по номеру группы показать студентов с наилучшей посещаемостью за заданный период.

Текущий порядок ввода: начальный год, конечный год, предмет, группа. Допустимы годы от 2000 до 2099 включительно; начальный год не должен быть больше конечного.

Текущий расчёт: год группы равен `2000 + последние две цифры группы + 3`. Если он не входит в период, программа сообщает, что занятий за период нет. Иначе для каждого студента считает число `1` и общую длину строк посещаемости в выбранных предметах. Сравниваются доли посещений. Выводятся все студенты с наибольшей долей в порядке списка группы. Для каждого показаны идентификатор, посещённые и все занятия, процент с двумя знаками. Если данных посещаемости нет, выводится `Нет данных посещаемости.`

Файлы посещаемости не содержат дат занятий. Поэтому текущая проверка периода опирается только на расчётный год группы. Соответствие этого правила требованию заказчика пока не подтверждено.

### F2. Максимум правильных ответов

Требование плана: по номеру группы показать студента с максимальным общим числом правильных ответов и само число.

Текущий порядок ввода: группа, затем предмет. Программа читает `TEST-*` выбранных предметов, отбирает строки по группе и идентификатору студента, суммирует число правильных ответов по попыткам. При равном максимуме показывает всех студентов в порядке списка группы. Формат результата: строка `Максимум правильных ответов: <число>`, затем `Студенты:` и список идентификаторов. Если подходящих результатов нет, выводится `Результаты тестирования отсутствуют.`

В текущем коде число ответов учитывается, если оно записано цифрами. Оценка для учёта попытки должна быть от `2` до `5`, со знаком `+`, `++`, `-` или `--` либо без знака. Студент без учтённых попыток не участвует в выборе лидера. Если число ответов корректно, а оценка нет, число ответов всё равно добавляется к сумме. Как обрабатывать такую ошибочную строку, нужно согласовать отдельно.

## 5. Пользовательские сценарии

1. Пользователь выбирает F1, вводит период, предмет и существующую группу. Программа показывает лидера или нескольких лидеров с долей посещения.
2. Пользователь выбирает F1 и период без расчётного года группы. Программа сообщает об отсутствии занятий за период.
3. Пользователь выбирает F2, вводит группу и предмет. Программа показывает максимальное число ответов и всех студентов с этим результатом.
4. Пользователь вводит неверный год, номер предмета или группу. Программа сообщает об ошибке и снова показывает меню.
5. Пользователь вводит `0` в главном меню. Программа завершает работу.

## 6. Ошибки и ограничения

- Если нет `students/groups` или `students/general/notes`, меню не открывается, ошибка выводится в stderr.
- Неверный период, предмет или группа вызывают сообщение об ошибке. После этого меню появляется снова. Код завершения всего процесса при такой ошибке может быть `0`, если пользователь затем выбрал выход.
- Отсутствующий файл посещаемости или `TEST-*` не останавливает программу. При отсутствии пригодных записей выводится сообщение об отсутствии данных.
- Формат F3 и F4 в v1 не определён.

## 7. Что уточнить у заказчика

1. Период F1 означает календарные даты занятий или расчётный год группы? В файлах посещаемости нет дат.
2. Сравнивать посещаемость по проценту или по числу посещений? Показывать всех лидеров при равенстве?
3. В F2 обязательна сумма по обоим предметам или пользователь может выбрать один предмет? Учитывать все попытки?
4. Показывать всех студентов при равном числе правильных ответов?
5. Как поступать со строкой теста, где число ответов корректно, но оценка неверна?

До ответа заказчика перечисленные правила расчёта описывают текущую реализацию, а не согласованное изменение требований.
